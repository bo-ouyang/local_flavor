# 社区内容化
> 优先级：P1 | 涉及模块：`community` + `exchange` + `messaging` + `items` + `frontend/uni-app` | 当前状态：社区基础闭环已完成，Phase 2 已部分落地

---

## 1. 当前项目状态

社区模块已经不是概念设计，当前真实代码里已经具备完整的一期闭环：

### 已落地的数据模型

- `CommunityPost`
- `CommunityComment`
- `CommunityPostLike`

### 已落地的业务规则

- 用户必须先完成交换，才能发布社区帖子
- 发布时只能选择自己参与过已完成交换的特产
- 评论别人帖子时，自己必须参与过该帖子对应特产的交换
- 评论支持多级回复
- 点赞需要登录

### 已落地的页面

- 社区列表页：`frontend/uni-app/src/pages/stats/map.vue`
- 社区详情页：`frontend/uni-app/src/pages/community/detail.vue`
- 社区发布页：`frontend/uni-app/src/pages/community/create.vue`

---

## 2. 本轮已新增落地

### Phase 1：社区治理

- 已接入 `Celery` 基础设施
- 帖子和评论新增审核状态、审核原因、软删除可见性字段
- 发帖和评论后会触发异步审核任务
- 社区列表和评论列表默认只展示“可见且审核通过”的内容
- 用户可删除自己的帖子
- 用户可删除自己的评论
- 帖子详情页支持审核状态提示和删除入口

### Phase 2：互动增强

- 已接入评论通知
- 已接入回复通知
- 已接入帖子点赞通知
- 已接入帖子审核通过 / 驳回通知
- 已接入“首次完成交换后解锁社区能力”的系统通知
- 社区列表已支持 `latest / hot` 两种排序
- 前端社区页已增加“最新 / 最热”切换入口

Phase 2 当前采用的实现方式是复用既有 `messaging` 会话和系统消息能力，而不是额外新建一套通知中心表结构。这样可以更快闭环，也更容易在小程序端复用现有消息页。

---

## 3. 当前真实接口能力

### 社区接口

- `GET /api/v1/community/posts`
- `POST /api/v1/community/posts`
- `GET /api/v1/community/posts/<post_id>`
- `GET /api/v1/community/posts/<post_id>/comments`
- `POST /api/v1/community/posts/<post_id>/comments`
- `DELETE /api/v1/community/posts/<post_id>`
- `DELETE /api/v1/community/posts/<post_id>/comments/<comment_id>`
- `POST /api/v1/community/posts/<post_id>/like`
- `GET /api/v1/community/eligible-items`

### Phase 2 相关增强

- `GET /api/v1/community/posts?sort=latest`
- `GET /api/v1/community/posts?sort=hot`
- 交换状态流转到 `completed` 后，会向首次完成交换的用户发送系统消息
- 评论审核通过后，会向帖子作者发送评论通知
- 回复审核通过后，会向被回复用户发送回复通知
- 帖子被点赞后，会向帖子作者发送点赞通知
- 帖子审核通过或驳回后，会向帖子作者发送审核结果通知

---

## 4. 当前权限与通知规则

| 场景 | 当前规则 |
|------|----------|
| 浏览社区 | 默认可浏览审核通过且可见的帖子 |
| 发布帖子 | 必须完成过交换 |
| 选择帖子关联特产 | 只能选择自己参与过已完成交换的特产 |
| 评论帖子 | 必须参与过该帖子对应特产的交换 |
| 点赞帖子 | 登录即可 |
| 点赞通知 | 他人点赞帖子后通知帖子作者 |
| 评论通知 | 评论审核通过后通知帖子作者 |
| 回复通知 | 回复审核通过后通知被回复用户 |
| 帖子审核结果通知 | 帖子审核通过 / 驳回后通知作者 |
| 社区解锁通知 | 用户第一次完成交换后发送系统消息 |

---

## 5. 排序策略

### 最新排序

- `created_at desc`

### 最热排序

当前先采用轻量实现：

- `like_count desc`
- `comment_count desc`
- `created_at desc`

这一版不引入复杂热度衰减公式，先满足“高互动内容优先曝光”的产品目标。后续如果社区帖子量明显增加，再考虑加入时间衰减和个性化权重。

---

## 7. 结论

社区内容化当前应被定义为：

`社区一期闭环已完成，二期已经进入互动增强阶段，当前重点从“能发能看”转向“能治理、能通知、能排序”。`

后续开发建议继续沿着这条路径推进，而不是回退到旧文档里那套更重、更偏理想化的社区模型。
