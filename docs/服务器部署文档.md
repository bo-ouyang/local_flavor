# Local Flavor 服务器部署文档

## 1. 适用场景

本项目当前前端是 `uni-app`，主要运行形态是微信小程序。

- 如果你上线的是微信小程序：服务器只需要部署 `Django API`。
- 如果你还要上线 H5：额外构建 `uni-app H5` 并交给 `Nginx` 托管。

下面文档默认服务器系统为 `Ubuntu 24.04`（Python 3.12）。生产环境应使用仍处于安全支持期的 Python 与 Django 5.2 LTS。

## 2. 代码上传到 GitHub

本地仓库初始化后，常用流程如下：

```bash
git init -b main
git add .
git commit -m "init: local flavor project"
git remote add origin https://github.com/你的用户名/你的仓库名.git
git push -u origin main
```

如果 GitHub 仓库已经提前创建好了，只需要把 `origin` 地址替换成你的真实地址。

## 3. 服务器目录建议

建议使用下面的目录结构：

```bash
/srv/local_flavor/
  backend_django/
  frontend/uni-app/
  static/
  venv/
```

## 4. 服务器基础环境

```bash
sudo apt update
sudo apt install -y git python3 python3-venv python3-pip nginx redis-server postgresql postgresql-contrib
```

如果你只想先跑通，也可以先用 SQLite，不上 PostgreSQL；但正式环境建议 PostgreSQL。

## 5. 拉取代码

```bash
cd /srv
sudo git clone https://github.com/你的用户名/你的仓库名.git local_flavor
sudo chown -R $USER:$USER /srv/local_flavor
cd /srv/local_flavor
```

## 6. Python 虚拟环境与依赖

```bash
cd /srv/local_flavor
python3 --version  # 必须为 Python 3.12.x
python3 -m venv venv
source venv/bin/activate
python -m pip install --upgrade pip
python -m pip install --require-hashes -r requirements.lock
python -m pip check
```

说明：

- `.python-version` 固定项目使用 Python 3.12；生产服务器也必须使用 Python 3.12.x。
- `requirements.in` 维护 10 项经审查的 Django 直接依赖；其中 `celery[redis]` 启用 Celery 官方 Redis transport，显式 `redis>=4.6,!=5.0.2,<6.5` 同时记录 Django RedisCache 的直接依赖，以及 Channels Redis 与 Kombu 元数据约束的交集。
- `requirements.lock` 固定 CI/生产使用的 49 个完整传递依赖和分发哈希；当前锁定 Celery 5.6.3、Kombu 5.6.2 与 redis-py 6.4.0，不应手工修改。
- 根目录 `requirements.txt` 是兼容入口，只引用同一份 `requirements.lock`，不会再安装已停用的 FastAPI 技术栈。
- 锁文件由 uv 0.9.5 使用 `uv pip compile requirements.in --python-version 3.12 --universal --generate-hashes --output-file requirements.lock` 生成；更新直接依赖后必须重新生成并在干净的 Python 3.12 环境验证。
- CI 会在非 eager 模式加载 Redis broker/result backend，并只对隔离的 Redis 7 服务执行无写入的 `PING`；不会投递任务或写入业务键。
- 当前前端启用了 WebSocket，推荐使用 Daphne 运行 ASGI；关闭 WebSocket 时也可以改用 Gunicorn 运行 WSGI。

## 8. 后端生产环境配置

先复制仓库中的安全模板：

```bash
cd /srv/local_flavor/backend_django
cp env.pro.example env.pro
```

然后编辑文件：

- `backend_django/env.pro`

至少要改这些值：

```env
DJANGO_DEBUG=0
DJANGO_ALLOWED_HOSTS=你的域名,你的IP
DJANGO_SECRET_KEY=请使用密码管理器生成的高强度随机值

DB_ENGINE=postgres
DB_NAME=local_flavor
DB_USER=local_flavor_user
DB_PASSWORD=请替换成强密码
DB_HOST=127.0.0.1
DB_PORT=5432

# AUTH-01A 与旧前端迁移部署必须三项一起修改：
AUTH_LEGACY_TOKEN_ENABLED=1
AUTH_WS_QUERY_TOKEN_ENABLED=1
AUTH_LEGACY_TOKEN_ACCEPT_UNTIL=请替换为未来90天内的UTC时间，例如2026-09-01T00:00:00+00:00

WECHAT_APPID=你的小程序AppID
WECHAT_SECRET=你的小程序Secret

CACHE_BACKEND=redis
CACHE_REDIS_URL=redis://127.0.0.1:6379/0

CHAT_ENABLE_WS=1
CHAT_REDIS_URL=redis://127.0.0.1:6379/1
```

上述认证截止时间必须是带时区的 UTC、位于未来且不超过 90 天。模板中的占位值故意不能启动；必须在首次执行 `migrate` 或启动任何 Django 进程前替换。AUTH-01B 覆盖后再把两个开关同时显式改为 `0`。

启动前设置环境变量：

```bash
export DJANGO_ENV=pro
```

进程环境变量优先于 env 文件（文件只填充尚未设置的键）。需要使用非默认文件时显式设置 `DJANGO_ENV_FILE=/绝对路径/env.pro`；可用 `DJANGO_LOAD_ENV_FILE=0` 完全禁用文件加载。默认 `env.dev/env.pro` 文件不得在加载过程中切换 `DJANGO_ENV`，避免先加载开发秘密再进入生产模式；危险组合会直接拒绝启动。

## 11. 使用 Supervisor 启动 Django ASGI

先安装 Supervisor：

```bash
sudo apt install -y supervisor
```

创建配置文件：

- `/etc/supervisor/conf.d/local_flavor.conf`

内容如下：

```ini
[program:local_flavor]
directory=/srv/local_flavor/backend_django
command=/srv/local_flavor/venv/bin/daphne -b 127.0.0.1 -p 8001 config.asgi:application
user=www-data
autostart=true
autorestart=true
startsecs=5
startretries=3
stopsignal=TERM
environment=DJANGO_ENV="pro"
stdout_logfile=/var/log/supervisor/local_flavor.out.log
stderr_logfile=/var/log/supervisor/local_flavor.err.log
```

重载并启动：

```bash
sudo supervisorctl reread
sudo supervisorctl update
sudo supervisorctl start local_flavor
sudo supervisorctl status
```

## 11.1 使用 Supervisor 启动 Celery Worker

说明：

- 开发环境 `env.dev` 中默认开启了 `CELERY_TASK_ALWAYS_EAGER=1`
- 这意味着本地开发时，即使不单独启动 Celery，任务也会直接在 Django 进程里同步执行
- 生产环境 `env.pro` 默认是异步模式，因此必须单独启动 Celery worker

项目内已提供启动脚本：

- Linux: `backend_django/scripts/start_celery_worker.sh`
- Windows: `backend_django/scripts/start_celery_worker.ps1`

如果你的服务器使用 `supervisor`，建议新增一个 worker 配置：

- `/etc/supervisor/conf.d/local_flavor_celery.conf`

内容如下：

```ini
[program:local_flavor_celery]
directory=/srv/local_flavor/backend_django
command=/bin/bash /srv/local_flavor/backend_django/scripts/start_celery_worker.sh
user=www-data
autostart=true
autorestart=true
startsecs=5
startretries=3
stopsignal=TERM
environment=DJANGO_ENV="pro",CELERY_CONCURRENCY="2",VIRTUAL_ENV="/srv/local_flavor/venv"
stdout_logfile=/var/log/supervisor/local_flavor_celery.out.log
stderr_logfile=/var/log/supervisor/local_flavor_celery.err.log
```

加载并启动：

```bash
sudo supervisorctl reread
sudo supervisorctl update
sudo supervisorctl start local_flavor_celery
sudo supervisorctl status
```

查看日志：

```bash
sudo supervisorctl tail -f local_flavor_celery
```

## 12. Nginx 反向代理

先创建 `/etc/nginx/conf.d/local_flavor_log.conf`。认证迁移期间旧版小程序的 WebSocket 仍可能把 Token 放在 query string，因此访问日志必须使用不包含 `$args`、`$request_uri` 或完整 `$request` 的格式：

```nginx
log_format local_flavor_safe
    '$remote_addr - $remote_user [$time_local] '
    '"$request_method $uri $server_protocol" $status $body_bytes_sent '
    '"$http_referer" "$http_user_agent" request_time=$request_time';
```

`$uri` 不包含 query string。不要在生产环境改回 Nginx 默认的完整 `$request` 日志格式；也不要记录 `Authorization` 请求头。

生产环境不接受认证兼容开关缺省。AUTH-01A 与仍只读顶层 legacy `access_token` 的旧前端必须原子部署：先把 `env.pro` 中 `AUTH_LEGACY_TOKEN_ENABLED=1`、`AUTH_WS_QUERY_TOKEN_ENABLED=1` 和明确的 UTC `AUTH_LEGACY_TOKEN_ACCEPT_UNTIL` 一起配置好，再启动新后端；截止时间必须在未来 90 天内，同时也是 query Token 的强制关闭日期。示例文件中的截止值故意无效，复制后不替换会拒绝启动。

AUTH-01B 前端确认已覆盖后，在同一个维护窗口显式设置 `AUTH_LEGACY_TOKEN_ENABLED=0` 与 `AUTH_WS_QUERY_TOKEN_ENABLED=0`，重启后端，再移除旧顶层字段。不要先关闭 legacy 再发布仍依赖顶层字段的客户端，也不要使用无截止时间的长期兼容配置。

创建文件：

- `/etc/nginx/sites-available/local_flavor`

内容如下：

```nginx
server {
    listen 80;
    server_name 你的域名 或 服务器IP;

    access_log /var/log/nginx/local_flavor.access.log local_flavor_safe;

    client_max_body_size 20m;

    location /django/api/v1/ {
        proxy_pass http://127.0.0.1:8001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /django/admin/ {
        proxy_pass http://127.0.0.1:8001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /ws/ {
        # AUTH-01A 临时措施：query Token 迁移期禁止 error_log 写入原始请求。
        error_log /dev/null emerg;
        proxy_pass http://127.0.0.1:8001;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 75s;
    }

    location /django-static/ {
        alias /srv/local_flavor/backend_django/django_static/;
        expires 7d;
    }

    location /static/ {
        alias /srv/local_flavor/static/;
        expires 7d;
    }
}
```

Nginx 官方 `error_log` 指令支持 `location` 上下文，日志级别包含 `emerg`：<https://nginx.org/en/docs/ngx_core_module.html#error_log>。上述 location 级 `error_log /dev/null emerg;` 是 AUTH-01A query fallback 期间的短期安全降级：upstream connect failure、timeout 等错误日志可能包含原始 request URI/query，因此不能在迁移期持久化。代价是 `/ws/` 的错误诊断和 OPS 告警暂时减弱。

AUTH-01B 改用 Authorization Header 并设置 `AUTH_WS_QUERY_TOKEN_ENABLED=0` 后，必须立即删除 `error_log /dev/null emerg;`，让 `/ws/` 恢复继承正常 error_log 与告警。不要宣称带 Token 的 query URL 可以安全记录。若前置 CDN、负载均衡器或云 WAF 会记录完整 URL，也必须同步禁记 query；无法做到时，在 AUTH-01B 前不得接收 query Token。

启用站点：

```bash
sudo ln -s /etc/nginx/sites-available/local_flavor /etc/nginx/sites-enabled/local_flavor
sudo nginx -t
sudo systemctl restart nginx
```

## 14. 微信小程序前端发布说明

微信小程序不是部署到你服务器上，而是：

1. 本地构建。以下命令在 `frontend/uni-app` 目录通过 `.nvmrc` 安装并使用 Node.js `22.23.2`，同时核对 npm `10.9.8`；任一版本不一致都会停止构建：

```bash
sudo apt install -y curl
export NVM_DIR="$HOME/.nvm"
if [ ! -s "$NVM_DIR/nvm.sh" ]; then
  curl -fsSL https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash
fi
. "$NVM_DIR/nvm.sh"

cd /srv/local_flavor/frontend/uni-app
nvm install
nvm use
[ "$(node --version)" = "v$(cat .nvmrc)" ] || { echo "Node.js 版本与 .nvmrc 不一致" >&2; exit 1; }
[ "$(npm --version)" = "$(node -p 'require("./package.json").engines.npm')" ] || { echo "npm 版本必须为 10.9.8" >&2; exit 1; }
npm ci --ignore-scripts --registry=https://registry.npmjs.org/
npm run build:mp-weixin
```

2. 打开微信开发者工具
3. 导入目录：

```bash
frontend/uni-app/dist/build/mp-weixin
```

4. 在开发者工具里上传并提交审核

说明：

- 小程序页面代码上传到微信平台
- 你的服务器只负责提供 API、图片上传、管理后台

## 15. 如果要部署 H5

如果你除了小程序，还想跑一个网页版本，同样必须通过 `frontend/uni-app/.nvmrc` 使用 Node.js `22.23.2` 并核对 npm `10.9.8`：

```bash
sudo apt install -y curl
export NVM_DIR="$HOME/.nvm"
if [ ! -s "$NVM_DIR/nvm.sh" ]; then
  curl -fsSL https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash
fi
. "$NVM_DIR/nvm.sh"

cd /srv/local_flavor/frontend/uni-app
nvm install
nvm use
[ "$(node --version)" = "v$(cat .nvmrc)" ] || { echo "Node.js 版本与 .nvmrc 不一致" >&2; exit 1; }
[ "$(npm --version)" = "$(node -p 'require("./package.json").engines.npm')" ] || { echo "npm 版本必须为 10.9.8" >&2; exit 1; }

```

然后把构建产物交给 Nginx，例如：

```nginx
location / {
    root /srv/local_flavor/frontend/uni-app/dist/build/h5;
    try_files $uri $uri/ /index.html;
}
```

注意：

- 只有当你明确要上线网页端时，才需要这一步
- 纯微信小程序项目可以跳过

## 18. AUTH-01B 会话与 WebSocket 上线要求

- 前端只会把当前会话凭据放入 `Authorization: Bearer <access token>` 请求头；不得为 API、上传或 WebSocket 拼接 token query 参数。
- 后端 query token 仅保留给设置了明确截止时间的旧版客户端迁移。它只能解析为 legacy token；新的不透明会话凭据即使以 `lf_a_` 开头，也不得因前缀被当作 legacy token。完成迁移后保持 `AUTH_WS_QUERY_TOKEN_ENABLED=0`。
- `VITE_API_BASE_URL` 必须是完整的线上 API origin（例如 `https://api.example.com/django/api/v1`），而 WebSocket 由同一 origin 派生为 `wss://api.example.com/ws/`。不要在生产包中使用相对地址、`localhost` 或仅有路径的地址。
- 开启 `CHAT_ENABLE_WS=1` 时，Channels、Daphne 与 Redis 依赖必须可导入；缺失依赖应让 ASGI 启动失败，不能静默退回到没有 WebSocket 的应用。浏览器 WebSocket 会经过 `AllowedHostsOriginValidator`，所以 `DJANGO_ALLOWED_HOSTS` 必须包含实际 H5 域名。没有 `Origin` 的非浏览器连接仅接受带非空 Bearer Authorization 请求头的客户端；没有 Origin 的 query token 连接一律拒绝。
- 上传接口只接受后端返回的同源 `/static/` URL。部署时必须确保 Nginx 的 `/static/` alias 指向受控上传目录；不要让 API 返回任意第三方 URL、`//host/...` 或 `/static/` 以外的文件路径。
- 登录、退出或切换账号会推进本地会话代数。正在进行的旧账号刷新不得覆盖或清除新账号会话；排查账号切换问题时不要通过手工写回旧 token 绕过该保护。
