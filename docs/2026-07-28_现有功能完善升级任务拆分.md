## 1. 目标与范围

本轮围绕已有链路继续升级：

```text
登录与定位 -> 发布特产 -> 审核 -> 搜索/推荐 -> 发起交换
-> 私聊协商 -> 双方确认完成 -> 评价/社区分享
```

包含五个阶段：

1. 工程安全与依赖升级。
2. 交换与聊天可靠性升级。
3. 推荐与搜索效果升级。
4. 发布与详情体验升级。
5. 社区互动体验升级。

明确不在本轮范围：

- 物流公司、运单号和物流轨迹。
- 待发货、已发货、待收货等物流状态。
- 收货地址和地址隐私管理。
- 平台支付、担保交易、退款和结算。
- 直播、电商店铺及重型黑盒推荐系统。

## 4. 任务粒度与完成标准

复杂度定义：

- `S`：单模块小改动，通常一个 PR。
- `M`：后端或前端含迁移/测试，仍应控制在一个 PR。
- `L`：跨后端、前端和部署，必须拆成连续 PR。

每个任务统一完成标准：

1. 先写能复现需求或缺陷的失败测试，再实现代码。
2. 新 API 保持统一响应信封，权限和非法输入有反向测试。
3. 涉及模型时提交迁移，并通过 `makemigrations --check --dry-run`。
4. 后端运行全量测试、`manage.py check` 和 `compileall`。
5. 前端运行 `type-check` 与微信小程序构建；交互任务补真机检查清单。
6. 性能任务必须包含查询数量或基准验证。
7. 同步更新开发文档、接口清单和任务状态。

### MSG-02 未读计数与已读回执正确性（M，P0）

- ACK 使用数据库单调更新，`last_read_seq` 不得回退。
- 部分 ACK 重新计算剩余未读，不能无条件清零。
- 历史 GET 不再隐式清零，统一由 ACK 修改并推送。
- 前端处理现有 `conversation.read` 事件，增加总未读徽标。

验收：部分、重复、乱序并发 ACK 和自发消息均有测试；历史查询无写副作用。

### MSG-03 WebSocket 重连与消息补偿（L，P1）

- 实现有限指数退避、jitter、网络恢复和回前台立即重连。
- 使用现有 ping/pong 加入心跳和超时判断。
- 页面隐藏时停止 WS、心跳、重连 timer 和轮询。
- 历史 API 增加 `after_seq`，重连后按本地最大 seq 补齐缺口。
- 区分 4401/4403 不可重试与临时故障。

验收：断线超过 30 条消息也不丢失；恢复后无重复；不可重试错误不进入重连风暴。

### Phase 2 推荐顺序

```text
EX-01 -> EX-02 -> EX-03 -> EX-04 -> EX-05
                         -> EX-06
MSG-01 -> MSG-02 -> MSG-03
```

### Phase 2 反模式守卫

- 不添加任何物流、运单、地址或收货状态。
- 不允许视图绕过状态服务直接赋值。
- 不只靠应用层“先查再写”处理并发幂等。
- 不让 Celery/Broker 失败把已经提交的业务状态伪装成失败。
- 不把 local storage 统计当作服务端业务事实。
