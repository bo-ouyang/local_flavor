# 特产交换小程序项目方案（2026-03-12）

## 1. 项目目标
- 产品定位：特产交换小程序（C2C），先跑通“发布 -> 匹配 -> 沟通 -> 交换确认”。
- 阶段策略：先完成交换闭环与风控基础，再扩展支付、物流、商业化。

## 2. 技术路线
- 后端：Django + Django REST Framework + MySQL + Redis。
- 前端：微信小程序（现阶段继续使用 uni-app 构建到 mp-weixin）。
- 部署：Nginx + Gunicorn/Uvicorn（ASGI）+ Celery（异步任务）。

## 3. 前端方案（已按要求调整）
- 首页：交换推荐流 + 多维筛选（分类/季节/保质期/可携带性），不做“同城推荐”入口。
- 发布页：发布可交换特产，填写“可交换条件”。
- 详情页：支持发起交换、风味投票、评论互动。
- 交换页：我的发起、收到请求、状态流转（待确认/已同意/已完成/已取消）。
- 消息页：会话列表、私聊、系统通知。
- 我的页：个人资料、我的发布、交换记录、信用分。

## 4. 后端模块设计
- accounts：微信登录、用户资料、地区信息、认证状态。
- catalog：特产主数据、图片、标签、筛选项。
- exchange：交换请求与状态机。
- social：评论、风味投票、举报。
- chat：会话与消息。
- ops：后台审核、风控规则、运营配置。

## 5. 数据与接口原则
- 统一 API 前缀：`/api/v1`。
- 统一鉴权：Bearer Token（后续切换微信 code2session + JWT）。
- 保持与现有接口尽量兼容，分阶段切换前端。

## 6. 里程碑
1. Django 重写基础层：项目骨架、模型、核心 API。
2. 前端改造：去同城首页，强化交换流程入口。
3. 交换闭环上线：交换请求 + 会话消息 + 状态流转。
4. 风控与运营：举报审核、内容治理、统计看板。
5. 扩展能力：物流、担保、信用体系、商业化。

## 7. 当前执行决策
- 立即开始后端 Django 重写。
- 首页不做“同城推荐”，改为“交换推荐 + 筛选”。

供给侧升级（B端）：引入合作社/商家“品牌馆”，从纯 C2C 扩展到 C2B2C。
