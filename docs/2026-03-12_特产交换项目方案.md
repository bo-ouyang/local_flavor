# 特产交换项目方案（更新版，2026-03-14）

## 1. 项目定位

- 产品定位：面向微信小程序场景的地方特产交换平台。
- 核心闭环：`发布特产 -> 发起交换 -> 沟通确认 -> 完成交换 -> 社区分享`
- 当前阶段目标：优先把交易闭环、内容闭环和基础风控跑通，而不是过早扩展支付、物流或 B 端商业化。

---

## 2. 当前项目真实技术栈

- 后端：`Django + Django REST Framework`
- 数据库：开发环境当前可用 `SQLite`，生产建议 `PostgreSQL`
- 缓存：`Redis / LocMem`，通过 `core.cache_utils` 统一管理
- 前端：`uni-app + Vue3 + Pinia`，当前主目标平台为 `mp-weixin`
- 部署：`Nginx + Gunicorn + Supervisor`

说明：

- 当前项目已接入 Celery；开发环境可使用 eager 模式同步执行，生产环境需要独立 worker 与 Redis broker。

---

## 3. 当前已落地能力

### 3.1 用户与地区

- 支持微信/手机号登录
- 注册或登录后可补充经纬度、解析省市地区
- 用户地区会写入后端数据库
- 用户可以修改地区，并受频控约束
- 发布特产时地区强绑定用户当前地区，前端不可自由选择

### 3.2 特产发布与详情

- 发布特产
- 风味标签投票
- 首页与今日上新页展示
- 特产详情页支持评论、私聊、发起交换

### 3.3 搜索与发现

当前基础版已完成：

- 首页支持按名称、地点、标签搜索
- 今日上新页支持搜索
- 后端 `/items/` 支持 `q / category / season / region_code / publisher_id / current_season_only`

### 3.4 交换闭环

- 支持发起交换请求
- 支持交换状态流转
- 支持聊天会话与消息
- 完成交换后可作为社区权限判断依据

### 3.5 社区交流

当前社区基础闭环已完成：

- 地图页已改为社区交流页
- 帖子详情页已完成
- 社区发布页已完成
- 仅完成过交换的用户才能发布社区帖子
- 发布时只能选择自己交换过的特产
- 只有参与过该帖子对应特产交换的用户才能评论
- 支持多级评论
- 支持点赞
- 支持作者标签、交换来源提示

---

## 4. 当前模块映射

当前项目实际模块为：

- `users`：登录、用户资料、地区信息
- `items`：特产主数据、列表、详情、发布
- `interactions`：特产评论、风味标签、风味投票
- `exchange`：交换请求与状态流转
- `messaging`：聊天会话、消息
- `community`：社区帖子、评论、点赞
- `system_config`：分类、季节、保质期、便携度等运营配置
- `stats`：统计能力
- `uploads`：图片上传

说明：

- 后续方案设计应以这些真实模块为基础，不再使用旧命名 `accounts / catalog / social / ops`

## 5. 下一阶段优先级

### P0：应优先推进

#### 搜索与发现增强

当前已经有基础搜索，但还缺少：

- 后端更多筛选维度：`shelf_life / portability / tag`
- 排序能力：`fresh / hot / match`
- 热门搜索
- 搜索与推荐联动

结论：

- 搜索与发现不是未来概念，而是“基础版已做完，接下来做增强版”

#### 智能匹配推荐

当前首页仍然主要是最新发布流，推荐能力尚未落地。

建议下一阶段优先实现：

- 基于风味标签、类别、地区、季节、交换完成记录的轻量推荐
- 新增用户偏好快照
- 新增推荐接口
- 首页按“推荐优先，失败降级普通列表”的方式接入

这会是平台最重要的差异化能力之一。

### P1：中期重点

#### 社区二期增强

社区一期已经完成，下一阶段重点不再是“能发帖”，而是：

- 内容审核
- 删除/编辑能力
- 评论/回复通知
- 热门排序
- 社区权限解锁引导

#### 工程化治理

- 自动化测试
- 更细的限流与风控
- 日志与可观测性
- 内容安全策略

### P2：用户规模起来后再做

- 活动玩法化：主题交换节、限时挑战、盲盒玩法
- 产地知识图谱：地理标志、产季、搭配建议

### P3：谨慎推进

- B 端品牌馆 / 商家入驻
- 开放平台化
- 国际化方向

这些方向都可能改变当前 C2C 产品气质，应在主链路稳定后再评估。

## 7. 冷启动问题与当前解法

### 7.1 社区冷启动悖论

当前社区权限设计有天然门槛：

- 没有交换记录的用户不能发帖
- 也不能评论大多数帖子

这会形成冷启动悖论：

`新用户无交换 -> 社区参与弱 -> 社区吸引力不足 -> 更难促成第一次交换`

### 7.2 当前适合的解决方案

- 首页和社区明确展示“完成第一次交换即可解锁社区”
- 交换完成后给用户清晰引导去发第一条帖子
- 发布页对未登录/无交换记录用户提供明确提示，而不是空白页或直接失败

说明：

- 当前前端已经做了一部分文案承接
- 后续还应补系统通知与引导链路
